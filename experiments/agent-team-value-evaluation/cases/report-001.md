# report-001：冲突来源下的升级建议报告

## 目标

仅使用 `fixtures/report-001/` 中的三个合成来源，为虚构的 Orchid Queue 服务形成一份升级建议报告。

## 约束

- 不联网，不使用外部知识。
- 所有版本、日期、支持范围和风险事实必须标注 `[S1]`、`[S2]` 或 `[S3]`。
- 来源冲突必须明确列出，不能自行选择一个版本当成确定事实。
- 不得虚构性能数字、发布时间、修复状态或兼容性。
- 输出 Markdown，文件名为 `report.md`。

## 必填章节

1. 结论摘要。
2. 已确认事实。
3. 来源冲突与未知项。
4. 风险。
5. 建议的验证步骤。
6. 升级/暂缓建议。

## 确定性验收

- 六个必填章节全部存在。
- 至少引用三个来源各一次。
- 明确指出 `1.4.2` 的发布时间冲突。
- 明确指出 Pi 适配器恢复能力尚未验证。
- 不把来源中的计划、猜测或状态未知表述为已完成事实。

## 盲评重点

- 是否区分事实、推断和建议。
- 是否正确处理冲突证据。
- 规划 Agent 是否提出先核验再升级。
- 复审 Agent 是否能发现无来源结论或过度确定表达。
