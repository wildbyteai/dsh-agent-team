# 外部 Agent 规划与复审价值对照评测

- 状态：方案已冻结，尚未调用真实模型
- 日期：2026-08-17
- 目的：证明外部规划、外部复审以及两者组合对 DeepSeek 任务交付质量的增量价值

## 评测问题

1. 外部规划是否提高任务一次完成率并减少重大返工？
2. 外部独立复审是否减少阻断级或高影响缺陷？
3. 同时使用外部规划和复审是否优于仅增加其中一个环节？
4. 质量收益是否值得额外的延迟、Agent 调用次数和人工介入？
5. 软件工程任务与非 Git 独立产物任务的收益是否一致？

## 对照组

所有变体使用相同任务、输入材料、权限、确定性验证器、时间上限和交付格式。

| 变体 | 规划 | 执行 | 复审 |
|---|---|---|---|
| D0 基线 | DeepSeek | DeepSeek | 无独立 Agent 复审 |
| D1 外部规划 | 外部规划 Agent | DeepSeek | 无独立 Agent 复审 |
| D2 外部复审 | DeepSeek | DeepSeek | 外部独立复审 Agent |
| D3 完整团队 | 外部规划 Agent | DeepSeek/指定执行者 | 外部独立复审 Agent |

确定性验证器不属于实验变量；四个变体都必须执行相同验证，避免把测试覆盖差异误认为 Agent 价值。

## 任务矩阵

### 冒烟轮

- 1 个 Git 软件工程任务。
- 1 个非 Git 独立报告任务。
- 每个任务运行四个变体各一次。
- 用于校准提示、评分表、日志脱敏和超时，不用于下最终结论。

### 正式轮

至少 8 个固定任务：

- 4 个 Git 任务：功能实现、缺陷修复、受约束重构、测试补全。
- 4 个非 Git 任务：调研报告、结构化文档、数据转换设计、低风险运维方案。
- 每个任务至少运行两次，运行顺序随机化。
- 输入材料使用公开、合成或脱敏数据，不使用公司业务数据和凭证。

任务需要在运行前冻结，不允许根据某个模型的特点临时修改验收规则。

## 评分方式

### 确定性评分

- 测试、构建、Lint、类型检查是否通过。
- 必填章节、引用、字段、格式和校验和是否完整。
- 是否违反权限、范围、文件或交付边界。
- 是否产生未授权副作用。

### 盲评评分

人工评审者不知道产物来自哪个变体，只依据冻结的 Rubric 评估：

- 正确性。
- 完整性。
- 约束遵循。
- 可维护性或可用性。
- 事实与证据质量。
- 风险和遗漏。

严重度统一为：阻断、警告、建议。不得由参与执行的 Agent 单独担任最终裁判。

## 核心指标

| 指标 | 说明 |
|---|---|
| 验收通过率 | 达到全部强制验收条件的任务比例 |
| 一次通过率 | 无整改即通过确定性验证和盲评的比例 |
| 加权缺陷分 | 阻断、警告和建议按冻结权重汇总 |
| 严重缺陷遗漏率 | 最终仍存在但未被复审发现的阻断问题比例 |
| 复审误阻断率 | 正确产物被错误标为阻断的比例 |
| 整改轮次 | 从首次产出到最终交付的返工次数 |
| 人工介入次数 | 计划修正、权限确认以外的额外干预 |
| 端到端耗时 | 从任务开始到可交付的墙钟时间 |
| Agent 调用次数 | 所有模型调用数量 |
| Token/用量 | CLI 能可靠提供时记录；不可得时标记未知 |

## 暂定判定门槛

这些是产品决策阈值，不是外部事实；必须在看到正式结果前冻结，冒烟轮后允许调整一次并记录理由。

完整团队 D3 相对 D0 至少应满足：

- 验收通过率提高至少 10 个百分点，或加权缺陷分下降至少 20%。
- 阻断级缺陷不得增加。
- 复审误阻断率不高于 20%。
- 中位端到端耗时不超过 D0 的 2.5 倍。
- 在高保证团队中允许更高成本，但必须由用户在任务启动前看到预算差异。

如果 D1 或 D2 与 D0 的差异很小，而 D3 没有额外显著收益，对应角色不应成为默认团队的强制节点。

## 运行协议

1. 冻结任务文本、输入、Provider/模型选择、权限、超时和评分 Rubric。
2. 为每次运行生成唯一 Run ID，不在提示中透露对照组名称。
3. 在新的隔离工作区运行；Git 任务使用独立 Worktree。
4. 保存结构化结果、产物引用和脱敏日志。
5. 先运行确定性评分，再进行盲评。
6. 所有变体完成后才揭示分组并汇总。
7. 失败、超时和空输出按预先定义的失败规则计入，不静默重跑。
8. 发布结论时区分事实、推断和产品建议。

## 安全与调用边界

- 本文档本身不授权调用任何真实模型或外部服务。
- 正式运行前必须展示冻结的任务材料、Reviewer/Provider、模型、调用次数、隔离方式和输出目录，并获得用户确认。
- 不安装、不登录、不修改 Provider 配置，不把公司资料上传给外部模型。
- 任何调用失败都保留原结果，不自动更换模型或 Provider。
