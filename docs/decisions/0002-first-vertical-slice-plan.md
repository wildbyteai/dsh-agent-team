# ADR-0002：首条纵向闭环实施计划

- 状态：无模型专家团切片与 Host→Browser Agent 名册连接已实现；任务运行投影连接、任务账本和 Adapter 待完成
- 日期：2026-08-17
- 目标：在不做后台孤岛原型的前提下，交付一条可见、可运行、可验证的端到端闭环

## 实施原则

- 每个增量同时包含最小 UI、运行逻辑、状态和验证，不按“后台 → UI”分层交付。
- 先完成一个真实路径，再扩展 Provider 和任务广度。
- UI 保留 Agent 小人、角色和状态表达，但不建立复杂动画系统。
- 不为尚未验证的 Provider 能力设计统一假象。
- 所有写入都小而可回滚；不自动修改当前分支或现有非 Git 目录。

## Gate 0：兼容性证据

源码与官方文档核验已经完成。已确定使用静态 Bundle、`settings.section`、`conversation.view`、插件自有任务账本和 Harness 受管子进程；Claude/Codex 为正式候选，Antigravity/Pi 为实验性。详见 `docs/decisions/0003-gate-0-compatibility-decisions.md`。

核心本机运行证据已经补齐：UI Slot、Settings、Conversation View、Workflow、Session 持久化/检查点、Subprocess、Host 退出时普通/PTY 进程树清理、Bundle/Profile 安装与生命周期、Browser 模块加载均通过官方测试。详见 `docs/tracking/gate-0-local-runtime-validation-2026-08-17.md`。

Gate 0 的正式最小 Host + Browser Bundle 已在 `packages/dsh-agent-team` 实现，并在临时 Profile 完成安装、Host 启动和 Browser Module Registry 冒烟。Agent 名册已经通过严格 Typert Remote Snapshot 接到 Browser，并在连接重置后重新扫描；任务运行投影、持久任务账本、假 CLI Adapter 和真实 Provider 回归仍未实现。

完成以下核验后才能创建正式插件脚手架：

1. Harness 能否注册独立管理页或现有等价入口。
2. Harness 能否在当前会话展示侧边运行状态或现有等价入口。
3. Workflow/后台任务是否提供节点事件、取消、超时和重启恢复。
4. Claude Code、Codex、Antigravity、Pi 的可控能力矩阵。
5. 是否能在不修改 Harness Core 的情况下完成首条界面和运行闭环。

输出：`docs/tracking/harness-provider-compatibility-2026-08-17.md` 和一份正式支持矩阵。

## 纵向切片 1：真实 Agent 面板

### 用户可见结果

用户打开面板即可看到 DeepSeek、Claude Code、Codex、Antigravity、Pi 的小人卡片，以及发现、路径、版本、冲突、鉴权和 Harness 适配状态。

### 最小实现

- 后端单一 Agent Registry。
- PATH 优先发现与已知目录补充扫描。
- 版本探测、超时和多安装去重。
- CapabilityReport 与健康状态。
- 渐进刷新和错误详情。

### 本切片不做

- 安装、升级、修复和卸载写操作。
- Provider 未验证能力的绿色“健康”状态。

### 验收

- 未安装、存在但不可运行、鉴权未就绪、适配器缺失、健康和实验性状态可区分。
- 同一 CLI 多路径安装可枚举，PATH 主入口清晰显示。
- 探测超时不会冻结整个面板。

## 纵向切片 2：默认团队与可视只读运行

### 用户可见结果

用户选择一个默认团队，看到规划、执行、验证、复审节点及 Agent 角色；启动一个只读任务后，任务图实时显示运行、交接、等待和完成状态。

### 最小实现

- 标准团队模板和可修改角色映射。
- 可信的团队快照、预算和超时。
- 一个通过 Gate 0 的规划 Provider 和一个复审 Provider。
- 权威 Run/TaskNode 状态与审计事件。
- 暂停、取消和失败显示。

### 验收

- Agent 输出不能直接改变权限、预算和任务完成状态。
- 用户可暂停、取消或向节点补充说明。
- 刷新界面后仍能读取已完成节点和产物引用。

## 纵向切片 3：Git 规划—执行—验证—复审—交付

### 用户可见结果

用户提交一个 Git 任务，确认计划后在隔离 Worktree 中完成实现，运行确定性测试，经独立复审和最多两轮整改，最后检查 Diff、验证结果和复审记录。

### 最小实现

- Worktree 创建、状态检查和安全清理。
- 单写入执行者。
- 测试/构建/Lint 验证器。
- 阻断、警告、建议三级复审。
- 本地任务分支、提交和 Patch 导出。

### 验收

- 当前工作区不会被任务执行直接修改。
- 阻断问题不能静默完成。
- 插件不自动应用、Push、建 PR、发布或部署。
- 用户放弃任务时明确展示将移除的临时 Worktree，不删除用户源文件。

## 纵向切片 4：恢复与降级

### 用户可见结果

Harness 或 Provider 中断后，用户看到任务最后安全节点、完成证据和可选动作；Provider 不可用时可选择明确降级的人工流程。

### 最小实现

- Run、节点状态、团队快照、产物引用和审计本地持久化。
- 只读节点和具有完成证据的节点恢复。
- 不确定副作用节点的人工核对状态。
- 用户计划、单执行者、确定性验证、人工复审降级流程。

### 验收

- 中断不会自动重复状态不确定的写入。
- 质量等级下降在界面和导出记录中可见。
- 所有 Agent 不可用时任务安全终止并保留产物。

## 纵向切片 5：非 Git 独立产物

### 用户可见结果

用户运行一个调研或文档任务，在插件任务目录中得到独立报告、来源/格式验证和独立复审结果。

### 最小实现

- 无工作区或任务目录 Workspace。
- Markdown/文档 Artifact。
- 必填章节、引用和格式 Validator。
- 与 Git 任务共用的角色、任务图、关卡和审计模型。

### 验收

- 调度引擎不依赖 Git 或 Diff 才能运行。
- 不修改用户现有非 Git 目录。
- 报告可连同计划、验证和复审记录导出。

## 纵向切片 6：价值对照评测

按照 `experiments/agent-team-value-evaluation/README.md` 运行 D0、D1、D2、D3 对照组，先完成冒烟轮，再经单独确认执行正式轮。

本切片的结果决定：

- 默认团队是否强制外部规划。
- 默认团队是否强制独立复审。
- 快速、标准、高保证三种模板的关卡差异。
- 对用户展示的时间与调用预算预期。

## 后续但不阻塞核心闭环

- Agent 生命周期安装、升级、修复和精确卸载。
- 更多 Provider。
- 自定义头像和更丰富的团队模板管理。
- 非 Git 有副作用任务。
- Windows、Linux、WSL。

生命周期写操作实现时必须继续采用：官方来源白名单、版本固定、计划与执行分离、明确确认、串行全局写入、脱敏日志和执行后重新探测。

## 首条闭环完成定义

- 至少一个规划 Provider、一个执行 Provider 和一个独立复审 Provider 通过能力验证。
- Agent 面板展示五个 Agent，未验证能力不会误报为正式支持。
- 一个 Git 任务和一个非 Git 独立产物任务完成完整可视流程。
- 权限、预算、超时、取消、阻断、两轮整改和人工降级可验证。
- Git 任务在 Worktree 中完成，非 Git 任务不修改现有目录。
- 中断后能恢复安全节点，不重复不确定副作用。
- 计划、产物、验证、复审和脱敏审计可查看和导出。
- 已完成价值对照评测冒烟轮；正式轮是否作为发布门槛由所有者在 Gate 0 后确认。
